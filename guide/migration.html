路径映射

旧新状态
git.enjoye.top/enjoydream/ekit/<pkg>github.com/oekit/<module>/<pkg>单体冻结维护，仅安全修复
github.com/oekit/<micro>（16 微库）github.com/oekit/pkg/<micro>微仓已删除；旧版本经 proxy 缓存仍可解析

一条命令完成 import 改写

# 单体微库：pkg/* → oekit/pkg/*（16 个包同理，逐包替换）
sed -E 's,git\.enjoye\.top/enjoydream/ekit/pkg/(errors|stringx),github.com/oekit/pkg/\1,g' main.go
# 门面：observability/logx → oekit/logx（逐仓对照见上表）
类型同一性：同一进程内所有模块必须使用同一个 oekit/pkg/errors。 混用旧 oekit/errors 会导致 BizError 的 As/Is 互相不识别（Not Found 变 500）。

API 变更对照（相对 ekit 单体）

旧（ekit 单体）新（oekit）说明
middleware 包（含 contrib）oekit/middleware（包名 mw）+ contrib 子包Round-2 拆出，Round-3 成独立仓
handler/crudh·validatorh（在 hertz 仓）oekit/handlerRound-3 拆出；hertz 主仓不再依赖 gorm
nns.MakeHTTPEndpoint / MakeGRPCEndpointoekit/nns-endpoint：endpoint.NewHTTPEndpointFactory(nnsClient.ServiceClient())Round-4 分家，工厂生命周期由调用方管理
observability/logx · metrics · tracingoekit/logx · oekit/metrics · oekit/tracingRound-2 解散 observability
workflow（在单体）oekit/workflow依赖 logx，独立成仓
examples/kitex（在单体）oekit/kitex-exampleskitex 主仓 shed bootstrap 链
